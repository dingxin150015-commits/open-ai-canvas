# 项目记忆维护规则

## 更新时机

每次完成重要分析、修改、测试、部署、迁移、事故处置或用户决策后更新。只改变措辞、格式或无关文件时无需更新。

## 更新方法

- 当前事实写入 `CURRENT_STATE.md`，旧事实移动到 `TIMELINE.md`，不要直接消失。
- 可复用教训和不可违反边界写入 `LESSONS.md`。
- 未完成工作、依赖、优先级和门禁写入 `BACKLOG.md`。
- 备份、快照、恢复材料、哈希、ACL、保留状态和替代关系写入 `BACKUP_REGISTRY.md`；只追加或标记状态，不覆盖历史登记。
- `README.md` 只负责入口和证据规则。

## 证据格式

重要结论至少附一种证据：

- Git commit/branch/diff；
- 绝对或仓库相对文件路径与行号；
- 测试命令、结果和日期；
- 容器镜像 ID、响应分块或日志时间；
- 官方文档路径、标题和 SHA-256；
- 用户明确批准或否决的范围。

## 状态词

- `已确认`：本轮有直接代码、配置、日志、测试或用户证据。
- `历史记录`：旧报告或旧测试曾成立，但未在当前版本复验。
- `推测`：有解释力但缺少直接证据。
- `待验证`：已有明确验证方法但尚未执行。
- `NO-GO`：继续执行会违反数据、授权、成本或正确性门禁。

## 安全与隐私

- 不保存 Token、Cookie、API Key、密码、密钥文件内容和用户数据正文。
- 凭据只记录“已验证/无效/来源不一致”等状态，不记录值。
- 真实外部调用、GitHub 写入、安装、容器变更和数据库操作不能仅凭记忆获得授权。

## 维护质量

- 新结论若推翻旧结论，要写明替代关系和原因。
- 新备份完成后必须先做完整性、恢复和权限验证，再登记为 `verified/protected`；旧备份未经批准只可标记 `superseded`，不可删除。
- 定期清理重复内容，但保留事故、关键决策和被推翻方案的摘要。
- 文档中的“完成”必须附当前验证；否则降级为“实现声明”或“历史记录”。
