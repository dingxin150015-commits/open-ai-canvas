# 关键经验、教训与注意事项

## v1.6.6 增量合并经验（2026-10-14 23:18 CST）

- 多文件apply_patch不是事务：保护目录失败前可能已有文件写入，不能整批盲重试。先检查实际diff和重复段；根项目记忆在保护目录内时，用已核实native apply_patch入口配合主机权限与LF参数，避免cmd/bat丢失多行参数。只机械去重完整相同的新段，不删历史证据。

- 首次从无静态卷旧Web迁到新web-data卷时，资产保留脚本不会凭空得到旧chunk。晋升前把旧容器静态资产复制到新卷，建立旧清单并touch副本mtime，发布后验证旧chunk的200与真实类型；不要把“同一新卷内第二次发布成功”误当作首次卷接入已覆盖。

- 产品更名不等于可以直接改IndexedDB/localforage/localStorage实现标识：无迁移地更名会使现有缓存不可见。保留旧namespace，采用新版算法，并检查image/media/drawing库和用户scope。不要仅更新硬编码夹具就误判通过。
- 合并“多输出堆栈”与已有索引子节点时，明确主节点/单输出子节点的职责；不要对带taskOutputIndex的子节点再次展开全部输出。回归要经过物化、持久、恢复和重放，不能仅比UI数量。
- 本地IndexedDB成功不能清掉远端冲突；生成回滚必须有字段来源，保留新普通编辑，并在并发删除时过滤空实体。上游“保留未确认工作”是恢复副本语义，不是允许自动重建云端删除画布。
- 新operations协议需要GET基线/PATCH operations/receipt/重读，旧PUT夹具不能机械放宽。独立跑通过而全套失败时先检查跨套件全局store/mock污染；保留全部断言，只按真实意图更新夹具。
- 跨Schema审计对同一旧字段集做稳定摘要；新增列不能被误认成业务数据变更。空官方夹具缺key要显式null，生产恢复必须有匹配key并真实解密/恢复；敏感副本与env仅存受限NTFS目录。
- root离线迁移后的副本属主必须适合app运行；Docker全internal网络可能不发布宿主端口，可仅让Web附加frontend，backend保留无外网路由。不得因此改全局代理或放开模型外联。
- 官方中文路径归档在Windows tar解包失败时，保留原归档并在Linux隔离容器解包，不把残缺源码当作官方事实。发布镜像源码标识在构建前固定，最终检查前后端同标识和实际容器ImageID。

## v1.6.0 增量合并新证据（2026-10-04 03:44 CST）

- 大文件被上游拆为多个新文件时，文本冲突中“本地整段函数”与“上游空段”不能直接保留两者：先比较函数集合与实现，再把本地唯一行为移入上游新位置。此次否则会在协议、管理、资源、画布和素材等模块造成重复定义或悄悄丢失百炼/本机能力。
- 画布提示词弹窗的两侧改动位于不同非冲突行，Git 自动合并留下两个同时 `open={expandedPromptOpen}` 的 Modal；类型和构建都通过，只有静态/交互检查暴露。自动合并重叠路径须复查 UI 的单实例约束。
- 上游新 Pi Agent 审批 waiter 与旧测试手动推进同一运行时会触发真实 Canvas revision CAS 竞争。只在旧测试辅助函数里关闭 waiter，生产 CAS 和异步路径不动；新增异步行为另有专门测试。单次全量偶发通过不等于稳定，重复目标夹具至少五轮。
- 系统渠道无调用检查不应分配 PTIER ID；档位 ID 只在正式保存前分配。任务订单须按最终请求规格重选价档，不能把旧前端 `priceTierId` 当真相；选中档位仍交现有 helper 校验，保留上游音频按秒和本地百炼实际时长两条计费路径。
- 旧 `CANVAS_ALLOWED_PRIVATE_UPSTREAM_HOSTS` 不再授权桌面本机渠道；本机媒体恢复测试必须显式启用 Runtime desktop 能力并令渠道 `AllowLocalChannel=true`，不能为测试把生产 SSRF 改成全私网许可。

## v1.5.8 合并新证据（2026-09-28）

- 2026-09-29：Linux CGO 真跑才暴露 Windows 仅编译门禁看不到的错误；旧 loopback 测试夹具必须按上游显式桌面能力更新，不能把生产 SSRF 改为“允许所有私网”。依赖齐全的全量还要逐个核实 PostgreSQL/Redis 测试确实 RUN/PASS，避免无声 SKIP。
- `go test ./...` 默认 10 分钟不适合当前大量 SQLite AutoMigrate 用例；超时栈显示 CPU 正在建索引，而非死锁。测试镜像与 CI 统一 `-timeout 30m`，不以反复碰运气取代失败归因。
- 任务错误要分离机器判断、用户安全文案与日志：内部 `providerPayloadError.raw` 可做精确协议分支，外部只允许类型化、经过 `providerErrorDetail` 过滤的短提示；一般 `err.Error()` 和上游原文不能直接写任务/调用日志。`ModelError` 嵌入 `AppError` 不自动满足 `errors.As`，需要明确 `Unwrap`。
- 桌面本机渠道的任务请求与同源媒体结果下载必须使用同一“服务端能力 + 渠道显式开关 + 精确回环同源”边界；旧全局私网环境变量不应给桌面功能授权。下载还要拒绝重定向、隐藏签名路径/Query。
- SQLite 在 WAL 文件已清理但仍采用 WAL 模式时，`sqlite3 -readonly` 挂只读卷可能因无法创建共享内存侧文件报 `unable to open database file`；先检查 DB 文件和 WAL/SHM 状态，在**隔离克隆**中允许目录侧文件写入、数据库仍只读打开做 integrity/foreign-key，不误判为数据损坏。生产卷不作此试探。
- 两谱系迁移必须用各自真正来源验证：本地旧 Schema9 用受保护备份的业务副本；官方 Schema40 用固定官方二进制建源卷再复制升级。官方空库结构通过不能代替旧业务保持；`migrate-schema up` 应重复执行并核对 key/registry/计数。
- Git 自动合并无冲突标记不等于配置可解析：4 份 Compose 的 `environment` 键被合出错误缩进，逐份 `docker compose config --quiet` 才暴露。以后每次合并都覆盖默认、本地、开发、Server、Deploy 和叠加 Build，生产仅用占位变量做静态检查，不打印真实环境值。
- Windows Bun 测试的 `file:` URL 不可用 `.pathname` 当本地路径，需 `fileURLToPath`；否则 `/D:/...` 被误当目录。测试依赖缺失是隔离工作树问题，不应因此恢复已删除的旧功能模块。
- 生成器可能静默降级独立 v4 包：旧 `generate-catalog.mjs` 不应重写百炼 v4 Manifest；打包只读取已验证的 v4 源，归档后逐字节对照。保护列表与脚本同时检验。
- Web 源码构建生成 Comfy Bridge 下载文件，不代表 Docker Web 镜像有这些文件。Dockerfile 必须在镜像上下文内交叉编译并复制，实际镜像构建/拉取文件仍是独立门禁。
- 设计 Issue 被关闭且标 `completed`，若没有维护者文字决策，不能替其推断 Schema/Adapter 取舍。正式上游 PR 从当时官方最新主线重新审计，移动 main 尾差不叠加到正在打开的固定标签 merge。

## 模型发现与执行资格必须分离

- 静态support_status不能同时决定编辑、启用和执行；手工新增与导入应由同一配置/插件合同判定。旧“only ready”记忆已由用户批准的统一资格方案替代，显式定价和请求级强校验仍保留。
- 不只查前端和service：Repository曾有两处ready SQL过滤，漏掉任一处都会导致配置成功但前台仍不可用。
- 无调用检查必须真正无写入；价格归一化曾分配PTIER序列，现将ID分配移到正式保存阶段，并测试检查配置不分配ID。
- 目录插件与执行插件须共享生命周期；v4模型合同与BuildCreate/BuildAgent共用。目录可见、配置通过和模型测试成功是不同证据层级。
- Gemini普通非Agent文本模板不会映射媒体，必须拒绝而不是静默丢弃；多模态Agent路径单独验证。缺媒体的本地拒绝不证明凭据或上游端点可用。
- 页面每页100条不是上游API每页100条；上游分页失败不得把部分结果作为完整目录同步。

## 单请求多结果必须贯通消费和恢复

- 只开放批量开关不够：画布消费不能固定 images[0]，恢复不能仅按 taskId 去重；需要持久输出序号、提交锚点、节点+任务恢复身份及逐输出副作用幂等。
- 显式目标已删除时不得退回同任务兄弟节点；单图重试须隔离原输出幂等身份，并在新任务绑定时重置输出序号。
- 显示开关和实际生成配置之外，报价配置也必须带入节点选项。测试夹具应具备有效模型渠道，不能因夹具被正常拒绝就放松生产模型门禁。

## 七模型完整能力复盘

- 旧 Provider 请求对照只能证明迁移等价，不能证明旧合同符合官网。长音频拒绝曾被错误测试固化，必须另补官网合法/非法输入测试。
- 空提示词需贯通页面、admission、worker、重试入口；只改一处不能消除使用阻断。
- Qwen OpenAI 兼容自动尺寸必须先把空值规范为 auto 再做字符串替换；表达式数组会省略 nil，直接 replace(nil,...) 会缺操作数。显式尺寸测试无法覆盖此问题，应保留完整模拟调用。
- 模型能力回归与生产克隆迁移采用不同网络边界：全量既有 Go 测试需要域名解析，完全断网会制造 DNS 失败；真实数据克隆仍必须断网。
- 新计费策略不能静默改变旧价格；实际用量、预估额、实际结算和 HTTP 耗时分别保存，缺上游可信终态用量不能按零结算。

## 百炼协议迁移复查

- 内存 shared-cache SQLite 的异步 Outbox 删除与断言读取可能产生 SQLITE_LOCKED；本轮两处夹具限定单连接后全量通过，未调整断言或生产连接池。不要通过反复重跑碰运气消除已定位的夹具竞态。
- 完整线协议迁移应使用正式声明式包和通用引擎扩展；新增参数语义使用 v3 包合同，让旧引擎加载时拒绝，而非忽略字段后提交残缺请求。

- 修改前必须核对当前工作树与稳定部署基线：旧 `b6254b41` 上的测试不能覆盖已晋升 `d9fec0f4` 的后续修复。
- Registry 可见不等于插件生命周期统一；新协议应从正式插件贡献进入目录，不能额外注入始终启用的宿主 Adapter。
- 媒体尺寸/时长存在于通用请求 metadata；实际迁移缺口包括原始参数缺省语义、尺寸换算和模型规则，不能误报为媒体信息完全缺失。
- 用旧 Provider 的冻结测试夹具比较完整请求，尤其是 false、-1、帧排序、区域路径和同源结果下载鉴权；测试通过后修改生产代码或插件包必须重新验证最终版本。

## TypeScript验证缓存隔离

宿主机产生的tsbuildinfo不得复制进容器或跨worktree复用。v1.2.7集成时，依赖未完整安装产生的诊断缓存进入镜像，导致大量旧错误；同镜像断网且incremental=false后只剩真实遗漏。Docker忽略必须覆盖 `**/*.tsbuildinfo`；发布门禁使用干净类型检查，不通过放松strict处理缓存问题。

## 数据与破坏性操作

- 永远不要在未获得用户对具体卷和数据范围的明确批准前执行 `docker-compose down -v`、卷删除、数据库替换或宽范围清理。
- 构建、前端缓存或容器更新问题不需要删除数据库卷。
- 数据迁移、权限修复和容器重建前必须做一致性备份，并验证恢复路径，而不仅是检查文件存在。
- `chmod 666` 只能视为临时应急结果，不是生产权限方案。
- D 盘是 exFAT，不能依靠 NTFS ACL 保护数据库、Token 或设置密钥；敏感恢复材料必须存入支持 ACL 的 C 盘用户私有目录，并逐文件复核权限。项目 D 盘只保留非敏感基线和位置指针。
- SQLite 恢复不仅需要数据库快照，还需要匹配的 `.settings-key`；必须同时验证完整性、外键、独立恢复副本和密文可解密性。
- `docker cp` 写入已收紧 ACL 的 Windows 私有目录时，复制出的文件可能不按预期继承可读 ACE；备份完成后必须逐文件复核并显式只授权当前用户、SYSTEM、Administrators，不能只检查根目录 ACL。
- 数据库审计脚本只在D盘保存计数、哈希和布尔结果；DB/WAL/SHM和`.settings-key`不得留在exFAT审计目录。临时Docker克隆卷验证后及时删除。
- 克隆启动必须对齐真实的插件与并发开关，并验证关键字段摘要和密文可解密性；只比表数和密钥文件哈希不足以证明业务数据未变化。

## Git 与上游合并

- 禁止 `git reset --hard`、宽范围 `git checkout --`、盲目 ours/theirs 和未经逐文件审阅的批量覆盖。
- 历史上批量 checkout 已经静默覆盖本地功能。今后每个冲突文件都要理解双方意图、编辑后立即做最小验证。
- `origin`、用户 Fork、官方上游和本地快照必须使用清晰名字；临时仓库不能冒充实时 GitHub 上游。
- GitHub CLI、Git Credential Manager、交互式 Shell 和 Codex 工具进程可能读取不同凭据。认证结论只对实际检查的进程成立。
- 在 Windows 上，受限进程无法读取 Keyring 时，`gh auth status` 可能把已登录账号误报为无效。应先在主机权限下复核 `gh auth status` 和 `gh api user`，再用显式 `--repo` 查询；不要因此把 Token 写入环境、文件、日志或项目记忆。
- “没有 PR”与“无法查询 PR”必须分开：查询成功且结果为空应报告未创建，不能循环触发认证修复。
- 上游贡献不能直接以本地长期开发 `main` 或陈旧 Fork 分支为 PR head。本地包含大量产品化功能和历史合并，必须在提交前重新获取官方最新 `main`，按单一贡献从干净基线重做或精确移植，并分别验证。
- 大型本地能力不能一次性作为巨型 PR 上游。先用中文设计 Issue 对齐数据模型和执行边界，再按“基础状态/门禁 → 单模型 Adapter → 目录 Manifest”拆成可独立审阅、回滚和测试的 PR。
- Issue 的 open/closed、标签、指派、点赞、订阅、交叉引用或普通贡献者回复都不是架构批准。有效决策至少要求回复者 `author_association` 为 `OWNER`、`MEMBER` 或 `COLLABORATOR`，且明确回答待决问题或明确接受文中推荐方案。
- “欢迎 PR”“可以试试”等笼统回复最多算 `partial`，不能据此替维护者选择 Schema 真相位置、非 Ready 行为、人工 Ready、Adapter 架构或 Manifest 形式。未回答项继续保持 NO-GO。
- GitHub 自动交叉引用可能由其他 Issue/PR 正文中的偶然编号触发。必须打开来源，核对主题、作者身份、正文上下文、评论和 Review；无关引用不能被误判为维护者响应。
- 对无回复的设计 Issue 不应高频催办。提交后先等待 2–3 个工作日，3–5 个工作日仍无回复时再申请用户授权发送一次结构化跟进；任何评论都是外部写入，不能从历史授权推导。

## 构建、部署和缓存

- 本项目浏览器真源是用户已登录的 Microsoft Edge。管理后台和 UI 证据只能从 Edge 获取；不要用 Chrome 或内置浏览器的登录状态替代 Edge 结论，也不要静默切换浏览器。
- `docker compose build` 成功不代表现有容器加载了新镜像；`restart` 也不会自动换镜像。
- 源码具备ffmpeg调用不代表运行镜像具备媒体能力；生产层和Linux测试层都要安装ffmpeg/ffprobe，并确认专项没有因缺依赖跳过。
- 新的页面流程可能让旧Service函数失去生产调用方。合并后必须沿路由、Handler、Service、Repository核对完整链路，尤其是“预览后再写入”这类交互改造。
- CI中的`bun run test`不自动等于仓库全测试；存在动态发现入口时，质量workflow应调用该完整入口并核对发现文件数。
- 必须比较源码提交、构建产物、镜像 ID、容器创建时间、HTML 引用分块和浏览器实际响应。
- Vite 带 hash 资源应使用内容寻址缓存；HTML 需要可重新验证。不要给所有静态资源统一 `no-store`。
- 健康检查不能替代登录、模型目录、任务创建、SSE、资源访问和生成链验证。
- Windows 沙箱内运行 Go 时，`GOCACHE` 和 `GOMODCACHE` 都必须定向到项目 `.local/cache`；只改 `GOCACHE` 仍会因用户模块缓存的 stat/lock 写入被拒绝。
- 当前主机 `CGO_ENABLED=0` 且没有 gcc/clang，而 Backend 的 GORM SQLite 驱动仍依赖 `go-sqlite3`。包编译成功不等于 SQLite 测试可运行；不得把 CGO stub 错误归因于业务代码，也不得为单次测试擅自安装全局工具链。
- Windows 的正确解决方式是隔离 Linux CGO test target，而不是切换生产 SQLite 驱动或安装全局 GCC。测试 target 必须不挂载数据库、卷和 `.settings-key`，并在执行前后核对现有容器未变化。
- Windows/exFAT 文件锁往返可能达到数秒。并发测试不得把 100/500 毫秒租约当成稳定墙钟，也不得断言两个独立定时器的绝对触发顺序；测试应验证 fence、续租和 FIFO 不变量，并让窗口明显低于但不贴近生产 30 秒合同。
- 原子文件替换允许观察者在 rename 窗口短暂读到 `ENOENT`；轮询型测试应重试该瞬时状态，但对其他 I/O/解析错误继续 fail closed。
- 不要在 Bun 的大规模共享测试进程中嵌入 Vite/Rolldown dev server 来加载普通业务模块；若业务代码可直接导入，应测试业务边界本身。确需 Vite 集成时使用独立进程并显式收束 worker 生命周期。
- 原生 worker panic 不能因为命令退出码为 0 就降级为无害告警；质量门禁应扫描 panic 签名并 fail closed，同时保留原始 stderr。
- 本机与 CI 的 Bun 版本必须来自同一版本文件；不能让本机 1.4.0、CI 1.3.x 各自验证不同运行时。

## 调试与证据

- 先确认真实路由、组件和调用方，再添加日志。不能在 Canvas 组件中加日志后，用 Create 页面没有日志推断缓存失败。
- 日志必须覆盖前端提交、API 入口、任务记录、Worker、Provider 请求和结果物化。某一层没有日志不等于请求未发生。
- 将“确认事实、推测、历史快照、待验证”分开。标题中的“完成”“根因确认”不构成证据。
- 静态代码阅读、编译成功、单元测试通过和真实 API 可用是四个不同验证级别。

## 模型能力与协议

- 内部能力、UI 展示值和上游传输格式必须分层。
- `auto`、比例和像素尺寸不是同一种值：Qwen Image 3 的 `auto` 应在适配器边界省略 `size`；内部像素使用 `x`，DashScope 传输边界再转换为 `*`；比例必须映射为模型允许的像素尺寸。
- 能力配置必须区分字段缺失、显式空数组和通配符。
- Catalog、UI、Admission、计费和 Provider 必须共享同一份有效能力；不允许目录补全而准入仍读原始 JSON。
- 系统渠道能力配置不能在读目录时单方面“智能补全”。持久能力缺失或损坏应让目录和任务准入同时 fail closed；官方 Ready 项必须在同步时写入完整模型专属能力。
- 正价格字段不等于已配置价格；公开目录、报价和任务路由必须同时要求 `price_configured=true`，以免管理员草稿意外对用户开放。
- 不允许 Provider 静默把 16 秒改 15 秒、480p 改 720p、截断参考媒体或忽略声明支持的参数。
- 模型限制应按具体 modelKey 建模，不能只按 DashScope 图片/视频协议给一套夸大的通用默认。
- 供应商“官方存在”与项目“执行器可用”必须用独立支持状态表示。官方目录项可以完整发现，但只有模型专属 Adapter 和测试完成后才能晋升为 `ready`。
- 上游百炼贡献的核心不是把更多模型 ID 塞进 discovery，而是让 Catalog、支持状态、能力、Admission、Serializer、异步轮询、结果解析和资源物化形成可证明的执行合同。只发现、只展示或只发出 HTTP 请求都不能称为 Ready。
- 百炼支持状态的五个架构选择必须在写代码前由维护者确认：Provider/ChannelModel 的真相分工、非 Ready 后台行为、人工 `ready/manual`、Adapter 所在层、Manifest 维护方式。未经确认直接迁移数据库会制造难以撤回的公共合同。
- 贡献 PR 中不提交完整百炼官方文档镜像，只提交必要的版本化元数据、公开文档链接、生成器和确定性测试。模型 API 精确合同继续以本地索引的官方 API 页为开发依据，但上游 PR 必须使用可公开复核的官方链接。
- 模型目录同步必须保留完整合同，不得先降级为字符串数组；对存量记录只能在停用、未定价、无能力配置时补齐，并用乐观并发条件保护管理员写入。
- 幂等不能只看主键没有新增。同步字段必须同时满足“当前缺失且目标非空”才算补齐；把空字符串写回空字符串也会改变 `updated_at`、制造错误的补齐计数，并让重复拉取产生无意义写负载。应以第二次拉取更新数为 0、业务字段加 `updated_at` 摘要不变共同证明幂等。
- 管理后台 toast 是观察入口，不是完整证据。遇到“新增 0、补齐 N”必须同时核对逐字段更新计数、数据库摘要和专项幂等测试，不能仅凭总行数不变判定成功。
- 同一协议下的 Wan 3.0、Wan 2.7 和 HappyHorse 不能共用参数归一化器。Wan 3.0 的 30 秒、480P、adaptive、智能时长和参考音频必须由精确 modelKey Adapter 处理；通用 DashScope fallback 只能服务尚未晋升 Ready 的模型。
- “智能时长”是上游 `duration=-1`，不是普通范围值。能力层要显式表示、UI 要保留该值、Adapter 要原样发送；按秒计费因预留时无法知道实际秒数必须明确拒绝，不能把 `-1` 当 1 秒或默认时长收费。
- 首帧/尾帧属于结构化角色，不等于普通参考图。必须按节点 ID 排序和验证，并拒绝与 `reference_image/reference_video/reference_audio` 混用。
- Provider 日志不得输出完整提示词、业务 Metadata、请求体或带签名的临时结果 URL；可记录模型、状态、是否收到 URL、请求/任务 ID 和脱敏错误分类。
- URL “只打印前 60 字符”和 API Key “首尾各 4 字符”都不是安全日志方案；签名查询参数和凭据片段仍可能泄露。只记录类型、数量、布尔状态和内部关联 ID。
- 每模型合同不仅包含各媒体类型上限，还可能包含跨类型约束：例如 Wan 2.7 R2V 的图片+视频总数最多 5、含视频时输出最多 10 秒。此类条件必须进入能力 JSON、逻辑模型投影、前端验证、Backend admission 和 Adapter，不能只写在 Provider。
- 文档声明上游会截断音频时，项目不应照搬静默行为；若已知音频时长大于输出时长，应在任务创建前明确拒绝。
- 同一账号主机可能同时提供 `/compatible-mode/v1` 与 `/api/v1`。调用原生 DashScope 时应保留配置中的账号/区域绑定 host，只替换协议路径；不能把 `/api/v1` 直接追加到兼容路径后，也不能擅自改成公共 DashScope host，否则 Token Plan/MaaS 权益可能失效。
- 供应商返回的签名结果 URL 属于不同信任域。下载时绝不能转发模型 API Key、租户头或渠道自定义头；只使用 URL 自带签名，并先执行出站 URL/SSRF 校验。
- 生成结果“已在浏览器本地物化”不等于“已进入平台 OSS”。`generation-image/video/audio:*` 必须被远端同步识别并从正确的 image/media 存储读取；资源上传失败应阻止远端资产确认并保留重试，不能吞错后保存不可跨设备使用的 `blob:` 地址。
- Docker 卷标记 `:ro` 和 SQLite `readonly:true` 不保证宿主文件零变化：SQLite 仍可能接触 WAL/SHM，root 容器会把共享文件变成 root 所有，导致非 root Backend 报 readonly。运行卷诊断必须使用服务相同 UID/GID，操作前后复核 DB/WAL/SHM owner/mode；更稳妥时使用一致性副本而不是在线卷。
- 自动镜像回滚不能修复共享卷权限事故。若新旧镜像都读取同一受损 WAL/SHM，回滚只会继续重启；必须先区分代码失败和数据卷权限失败。
- 系统渠道的价格有效不等于所选 SKU 有价格。创建任务时必须用完整 intent（operation、分辨率、时长、参考数量）匹配具体价格档，再把 price tier ID 固化进账单；不能退化为空规格匹配或用通配档绕过授权范围。
- 能力 JSON 声明参数受支持不等于 Create 已提供控制入口。付费调用前必须从真实路由核对每个影响费用/输出的参数；隐藏的全局默认同样会进入请求。对支持音频或水印的视频模型，Create 必须显式展示开关和当前摘要，不能让旧默认静默决定上游 payload。
- Go 的结构体嵌入不会自动让外层错误满足 `errors.As(..., *AppError)`；领域错误若要沿错误链投影，必须显式实现 `Unwrap` 并用测试锁定 HTTP 状态、公开错误码、分类和 retryable。
- 请求编号是诊断关联键，不是可信用户正文。只允许有界 ASCII 标识字符，响应头、响应体、访问日志和业务日志必须使用同一规范化值；前端也必须再次校验后才能展示。
- 安全日志不能只过滤 API Key。提示词、text/content/input/output、Provider message、签名 URL 和任意非结构化错误都可能包含用户内容或凭据；默认只保留 ID、分类、计数、布尔状态、HTTP 状态、耗时和 Go 错误类型。
- Local Runtime 的 master token 只服务遗留内部边界，不能作为浏览器深链凭据。网页连接必须依赖精确可信 Origin、浏览器不可导出密钥、挑战交换和逐请求签名；启动 URL 只表达 `mode`。
- Vite 备用端口必须同时更新网页实际 Origin 和 `FRAMEFIELD_TRUSTED_WEB_ORIGINS`。`CANVAS_URL` 不会配置当前 Agent，Next 命令也不适用于本项目；端口属于其他进程时不得强杀或冒充 Runtime。
- MCP 超时必须大于最慢业务续接窗口，而不只是大于普通工具超时；35 分钟生成续接使用 36 分钟外部 MCP 合同，留出终态序列化和进程清理余量。
- ORM 的“参数化日志”选项不保证覆盖 Raw SQL 已预插值的错误路径。生产日志若可能接触提示词、账号或凭据，应整体隐藏 SQL 文本，只保留错误、文件、耗时和行数；同时单测必须包含 Raw 查询失败。
- 报价不能维护一套独立的客户端价格算法。统一目录、任务 admission、精确 SKU 选择、倍率和 Token 估算必须共用服务端合同；报价只返回快照，不能写账务或冻结积分。
- 只定义但不迁移、不读写的 ORM 结构不是“未来功能”，而是误导性死合同。确认从未进入 schema 后应删除并校正历史文档，不为死类型创建兼容表。

## 外部调用与成本

- 真实百炼、OpenAI 或其他 Provider 调用前必须确认供应商、账号、模型、区域、参数、预计费用和重试次数。
- 不得在未授权时静默更换模型、区域、协议、账号或代理，也不得用多次真实调用代替本地测试。
- 临时输出 URL 可能过期，验证与持久化应及时处理，不能把上游临时 URL 当长期资产。

## 文档和自动化权限

- `.claude/` 是历史档案，不是当前执行指令；其中命令不得自动重放。
- 项目文档必须与当前路径、脚本、环境变量和 Compose 一致。
- 自动授权应默认只读；Git 写入、Docker 变更、安装、网络、数据库和进程终止必须逐次确认。
- 重要新经验要写入项目记忆，而不是只留在单次对话或临时报告中。
