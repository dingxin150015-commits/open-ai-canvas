# 系统模型目录与配置资格

拉取模型只发现模型名称与上游信息，不自动定价、启用或证明账号可调用。目录中的 `unknown`（未分类）、`planned` 等标记不再决定整个编辑器是否只读。

## 配置流程

1. 在系统渠道中拉取模型，或手动新增；两种来源使用相同的后端配置及执行校验。
2. 选择输出能力、已安装协议和精确上游模型 ID，补齐能力参数及规格价格。
3. 可以先「保存停用草稿」。草稿不会开放调用，不能用草稿标记绕过真实测试或执行校验。
4. 「检查配置（不调用上游）」只校验本地配置，不创建模型、订单、任务或分配 ID，也不请求供应商。
5. 通过配置校验后可明确启用。实际模型测试会请求供应商，可能产生费用；配置校验不证明凭据、额度、端点或生成质量有效。

Gemini 原生文本、图片和 Veo 是不同协议；不能把 TTS、Embedding 等目录项一律当文本。缺少相应执行插件的模型保留草稿，不能强制启用。自定义代理应选择代理实际支持的协议，不按渠道显示名称或模型名称猜测厂商。

## 后端资格投影

管理员模型 API 返回只读 `eligibility`，包含 `canEditConfiguration`、`configurationValid`、`executionSupported`、`canEnable`、`canExecute`、原因码、可读原因及协议版本。该对象不进入数据库，是根据现有配置和当前插件注册表派生的模型级结果；实际调用还检查渠道、用户权限、配额和请求参数。

目录、模型配置、逻辑模型线路、报价、系统渠道解析、计费入口和任务准入共用资格判定。数据库只按身份及启用状态查询候选，不以静态目录状态代替服务层的执行合同。

## 插件合同与发现

`yingce.plugin/v4` 的 `contributes.providers[]` 可声明：

- `modelContract.mode=exact` 及 `models`：精确模型集合，配置和请求序列化均校验。
- `modelContract.mode=compatible`：声明兼容协议，可配置新的模型 ID；不是账号或原厂模型认证。
- `modelCatalog.hosts/entries`：受控主机的补充目录事实，使用同一插件加载、升级、启停与卸载生命周期，不另设目录插件开关。

使用上述字段的包必须声明 v4；旧宿主拒绝加载，不能忽略模型约束继续执行。没有新增约束的既有包沿用原协议合同，仍受配置、请求级校验和实际插件可用性限制。

百炼静态文档目录保留为生成资料，运行时从正式协议包读取补充目录；支持集合由执行规格生成。已有七模型与快照之外的模型不会因为目录可编辑而自动获得执行适配。

## 分页与存量保护

Gemini 原生目录读取 `displayName`、`supportedGenerationMethods`，通过 `nextPageToken` 同源翻页。页面的 100 条/页只影响显示，与上游分页独立。最多 100 页、10000 个目录项和 2 分钟；重复/超长游标、响应错误、超限或取消均中止，不导入部分结果。

目录补全只更新符合条件的未配置记录，已配置的价格、启用状态及模型 ID 不自动改写，不因一次目录缺项删除模型。已经保存的配置在插件状态变化后重新评估资格，不依赖重新拉取来解除旧的目录标记。

## 代码与 API

- `channel_model_eligibility.go`：统一资格判定及无调用配置检查。
- `channel_model_catalog.go`：受控目录 GET、Gemini 字段与分页。
- `channel_model_catalog_plugin.go`：当前协议注册表的目录贡献投影。
- `protocol/model_contract.go`：版本化模型合同和目录声明校验。
- `POST /api/admin/channels/:id/models/validate`：管理员配置检查，使用业务 API 统一响应。
- 模型保存请求的 `draft: true` 强制保存为停用状态；价格仍由现有服务层校验。
